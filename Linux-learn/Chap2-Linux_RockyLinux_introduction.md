# 리눅스와 Rocky Linux 소개

## 2.1 리눅스의 개요

### 2.1.1 리눅스의 탄생

1991년 8월 대학생이었던 리누스 토르발스(Linus B. Torvalds)는 어셈블리어로 리눅스 커널 0.01 버전을 처음 작성했다. 그 당시 리누스 토르발스의 목표는 유닉스 시스템의 작은 버전인 미닉스보다 좋은 운영체제를 만드는 것이었다. 이후 1992년에 0.02 버전의 소스 코드를 인터넷에 공개하면서 리눅스가 탄생했다.

흔히 현재의 리눅스를 리누스 토르발스가 혼자서 개발한 것으로 오해하는 사람이 많다. 실제로 리누스 토르발스는 커널(Kernel)이라고 부르는 리눅스의 핵심 부분만을 작성해 배포했다.

> 일반적으로 우리가 얘기하는 리눅스는 리누스 토르발스가 만든 커널에 컴파일러, 셸, 기타 응용 프로그램이 조합된 배포판을 의미한다.

- 일반적인 리눅스 배포판의 구성

```
하드웨어(CPU, RAM, HDD 등) < 커널(엄격한 의미의 리눅스) < 셸(명령어 해석기; bash, csh 등) < 응용프로그램(에디터, 통신 프로그램, X 윈도, 웹 서버, DB 서버)
```

### 2.1.3 커널

커널에는 현재 제어하는 하드웨어 장치의 지원 여부 관련 정보, 하드웨어 성능 정보, 하드웨어 제어 코드 등이 들어 있다. 리누스 토르발스는 이 '커널'이라고 부르는 리눅스의 핵심을 개발했고 지금도 계속 업그레이드를 진행하고 있다.

1. 커널의 개념: 운영체제의 심장

'커널(Kernel)'은 영단어 뜻 그대로 '알맹이' 또는 **'핵심'**을 의미한다.

소프트웨어가 컴퓨터 하드웨어(CPU, 메모리, 디스크 등)를 직접 제어하려고 하면 충돌이 발생하거나 보안상 심각한 문제가 생길 수 있다.
커널은 하드웨어와 응용 프로그램(또는 사용자) 사이에 위치하여 하드웨어를 추상화하고, 자원을 효율적이고 안전하게 관리·분배하는 중재자이자 운영체제의 핵심 엔진.

컴퓨터가 부팅될 때 가장 먼저 메모리에 로드되어 전원이 꺼질 때까지 상주하며 시스템의 모든 것을 감시하고 제어한다.

2. 커널은 무엇으로 만들어졌을까? (개발 언어)

리눅스 커널은 주로 C 언어와 **어셈블리어(Assembly)**로 작성되어 있으며, 최근에는 Rust가 추가되었습니다.

- C 언어 (약 95% 이상):
  - 커널의 대부분은 C 언어로 구현되어 있습니다. 하드웨어를 직접 제어할 수 있을 만큼 저수준(Low-level) 제어가
    가능하면서도, 다른 CPU 아키텍처(x86, ARM, RISC-V 등)로의 이식성(Portability)이 뛰어나고 실행 속도가
    매우 빠르기 때문입니다.
- 어셈블리어 (약 1~2%):
  - CPU가 부팅되는 극초기 단계의 코드, 레지스터를 직접 조작해야 하는 코드, CPU 종류마다 완전히 다른 명령어를 처리해야 하는
    극히 일부분(하드웨어 종속적인 부분)에 사용됩니다.
- Rust (최신 트렌드):
  - 2022년 말 리눅스 커널 6.1 버전부터 메모리 안정성이 뛰어난 'Rust' 언어가 공식 개발 언어로 채택되어, 주로 장치
    드라이버 개발을 중심으로 사용 비중이 점차 늘어나고 있습니다.

3. 커널의 5대 핵심 역할

커널은 시스템의 자원을 관리하기 위해 다음과 같은 5가지 핵심 기능을 수행한다.

1.  프로세스 관리 (Process Management)
    - CPU가 여러 프로그램(프로세스)을 동시에 실행하는 것처럼 보이게 해주는 **스케줄링(Scheduling)** 을 담당함.
    - 프로세스의 생성, 실행, 대기, 종료 및 프로세스 간의 통신(IPC)을 제어함.

2.  메모리 관리 (Memory Management)
    - RAM(물리 메모리)을 프로세스들에게 안전하게 할당하고 회수함.
    - 각 프로세스가 서로의 메모리 영역을 침범하지 못하도록 격리하며, 물리 메모리가 부족할 경우 하드디스크의 일부를 메모리처럼 쓰는 가상 메모리(Virtual Memory) 기법을 제어함.

3.  파일 시스템 관리 (File System Management)
    - 디스크에 데이터가 어떤 규칙으로 저장되고 읽히는지를 관리함. (예: ext4, XFS 등)
    - 리눅스의 철학인 **"모든 것은 파일이다(Everything is a file)"** 를 구현하여, 하드웨어 장치나 네트워크
      소켓까지도 파일 형태로 추상화해 응용 프로그램이 쉽게 접근하도록 도움.

4.  장치 드라이버 관리 (Device Driver Management)
    - 그래픽 카드, 키보드, 마우스, 네트워크 카드 등 수많은 입출력(I/O) 장치를 제어함.
    - 제조사가 만든 하드웨어와 커널 표준 인터페이스를 연결해 주는 '드라이버'를 통해 프로그램들이 장치의 세부 규격을 몰라도 하드웨어를 사용할 수 있게 해줌.

5.  네트워크 관리 (Network Management)
    - 인터넷 통신을 위한 표준 프로토콜(TCP/IP, UDP 등) 스택을 커널 내부에 구현하고 있음.
    - 네트워크 카드를 통해 들어오고 나가는 데이터 패킷을 검사하고 전송 경로를 제어함.

💡 [참고] 시스템 호출(System Call)이란?

> 사용자가 실행하는 일반 응용 프로그램(User Space)은 안전을 위해 하드웨어에 직접 접근할 권한이 없습니다. 파일 저장, 화면 출력 등 하드웨어 자원이 필요할 때 커널(Kernel Space)에 정중하게 작업을 부탁하는 창구를 **'시스템 호출(System Call)'** 이라고 부른다.
