# Rocky Linux 설치

Rocky Linux는 백그라운드로 새로운 패키지를 자동 업데이트하도록 설정되어 있다. 업데이트가 자동으로 되지 않도록 자동 업데이트 기능 꺼두는 법

```bash
gsettings set org.gnome.software download-updates false
gsettings set org.gnome.software allow-updates false
systemctl disable dnf-makecache.timer
```

### X 윈도 시스템

> X 윈도 시스템은 리눅스와 유닉스 대부분에서 사용되는 그래픽 환경 기반의 시스템 소프트웨어로, 1984년 미국 MIT에서 최초로 공개한 이후 지금까지 보편적으로 사용되어 왔다. Server나 Client 가상머신의 GNOME 데스크톱은 X윈도를 기반으로 작동하는 GUI 환경이다. MS Windows에 그래픽 환경이 없다면 거의 사용할 수 없지만, 리눅스의 X 윈도는 하나의 응용프로그램일뿐이며 필수적이지 않다. 그래서 아직도 많은 리눅스/유닉스 서버는 X 윈도 없이 텍스트 모드로만 사용한다. 텍스트 모드를 사용하면 얻게 되는 가장 큰 장점은 적은 컴퓨터 자원을 사용하기 때문에 동일한 성능의 컴퓨터에서 더 빠른 고성능 서비스가 가능하다는 점이다. 참고로 요즘의 리눅스는 X 윈도의 문제점을 보완하기 위해 완전히 재설계한 차세대 시스템인 Wayland를 사용하고 있다. 즉, 예전의 리눅스는 커널 $\rarr$ X 윈도 $\rarr$ GNOME 데스크톱 구조를 사용했다면, 현재는 커널 $\rarr$ Wayland $\rarr$ GNOME 데스크톱 구조를 사용하고 있다.

### 3.1.4 리눅스 GUI 환경: X 윈도와 차세대 시스템 Wayland

리눅스는 본래 텍스트 기반(CLI)으로 설계되었으나, 데스크톱 사용자 편의를 위해 그래픽 사용자 인터페이스(GUI) 환경을 제공합니다. 이를 구현하는 핵심 기술이 **'디스플레이 서버 시스템'** 이며, 전통의 **X 윈도(X Window)** 와 차세대 표준인 **웨이랜드(Wayland)** 가 있습니다.

---

#### 1) X 윈도 시스템 (X Window System, X11)

X 윈도 시스템은 1984년 미국 MIT에서 유닉스 계열 운영체제를 위해 개발한 전통적인 그래픽 디스플레이 시스템입니다. 현재 사용되는 버전은 11번째 판으로, 줄여서 **'X11'** 이라고도 부릅니다.

- **네트워크 투명성(클라이언트-서버 구조)**:
  - X 윈도는 독특하게도 내부적으로 **클라이언트-서버 구조**로 작동합니다.
  - 화면을 표시하고 입력 장치를 제어하는 'X 서버'와 실제 연산을 수행하는 'X 클라이언트(응용 프로그램)'가 네트워크를 통해 통신합니다. 이 덕분에 **원격지에 있는 고성능 서버의 GUI 프로그램을 내 컴퓨터 화면에 띄우는 것(X11 포워딩)** 이 기본적으로 가능합니다.
- **선택적 컴포넌트(GUI의 독립성)**:
  - MS 윈도우는 커널과 GUI 시스템이 깊게 결합되어 있어 GUI를 끌 수 없지만, 리눅스에서 X 윈도는 **단순한 하나의 응용 프로그램**에 불과합니다.
  - 따라서 성능과 안정성이 최우선인 기업용 서버(Server) 환경에서는 자원을 아끼기 위해 X 윈도를 설치하지 않고 가벼운 **텍스트 모드(CLI)** 로만 운영하는 것이 일반적입니다.

---

#### 2) 왜 Wayland(웨이랜드)가 개발되었는가? (등장 배경)

약 40년간 표준으로 군림했던 X 윈도는 현대 컴퓨터 환경에서 심각한 한계에 부딪혔습니다. 이를 대체하기 위해 2008년, 레드햇(Red Hat)의 개발자 크리스티안 회그스베리(Kristian Høgsberg)가 주도하여 **웨이랜드(Wayland)** 프로젝트를 시작했습니다.

- **심각한 기술적 부채와 비효율성**:
  - 1984년에 설계된 X 윈도는 '중앙 서버가 그래픽 렌더링을 직접 계산하던 시절'의 아키텍처입니다. 현대에는 GPU(그래픽 카드)가 렌더링을 직접 처리하므로, X 서버는 쓸데없이 중간에서 메시지만 전달하는 **비대하고 느린 중개자**로 전락했습니다.
- **보안 취약점 (Keylogging & Screen Scraping)**:
  - X 윈도에서는 모든 응용 프로그램이 동일한 메모리 버퍼를 공유합니다. 즉, 악성 프로그램 하나가 몰래 다른 창의 키보드 입력을 가로채거나(키로깅), 다른 창의 화면을 캡처하는 보안 문제가 구조적으로 방치되어 있었습니다.
- **화면 찢어짐(Tearing) 및 다중 모니터 문제**:
  - 주사율(Hz)이나 해상도(HiDPI)가 다른 모니터를 여러 대 연결할 때 배율 조절이 어렵고, 화면 갱신 주기가 맞지 않아 화면이 찢어지는 현상(Tearing)이 자주 발생했습니다.

#### 3) Wayland의 아키텍처 및 특징

> **💡 Wayland는 단일 프로그램이 아닌 '통신 프로토콜 규격'입니다.**  
> 즉, "화면을 그릴 때 이렇게 통신하자"는 규칙이며, 이를 구현한 주체를 **'컴포지터(Compositor)'** 라고 부릅니다.

- **단순화된 구조 (지연 시간 최소화)**:
  - X 윈도는 `[앱] ↔ [X 서버] ↔ [윈도우 매니저] ↔ [하드웨어]`를 거치는 복잡한 단계가 있었습니다.
  - Wayland는 윈도우 매니저와 디스플레이 서버를 하나로 통합한 **'Wayland 컴포지터'** 가 하드웨어(커널의 DRM/KMS) 및 응용 프로그램과 직접 소통합니다. 불필요한 중간 단계가 제거되어 **반응 속도가 빠르고 화면 깜빡임이 없습니다.**
- **강력한 보안 격리**:
  - 각 응용 프로그램은 오직 **자신의 창 화면만** 렌더링할 수 있습니다. 운영체제의 명시적 허가 없이는 다른 프로그램의 입력을 엿듣거나 화면을 캡처할 수 없습니다.

```
[ 전통적인 X11 구조 ]
응용프로그램(Client) ⇄ [ X 서버 ] ⇄ [ 윈도우 매니저 ] ⇄ 커널(하드웨어)

[ 현대적인 Wayland 구조 ]
응용프로그램(Client) ⇄ [ Wayland 컴포지터 ] ⇄ 커널(하드웨어)
```

---

#### 4) 현재 Wayland의 도입 현황

Wayland는 이미 차세대 기술 단계를 넘어 **현대 리눅스의 기본 표준(Default)** 으로 완전히 자리 잡았습니다.

1. **주요 배포판의 기본값 채택**:
   - **Fedora**: 리눅스 진영 중 가장 먼저 기본 디스플레이 서버로 전환했습니다.
   - **RHEL 및 Rocky Linux**: **Rocky Linux 8 및 9**에서 GNOME 데스크톱을 사용할 경우 **기본(Default) 디스플레이 서버로 Wayland가 작동**합니다.
   - **Ubuntu**: 21.04 버전부터 Wayland를 기본값으로 완전히 전환했습니다.
2. **X11의 퇴장 예고 (Deprecation)**:
   - 레드햇(Red Hat)은 차기 버전인 **RHEL 10(및 호환 배포판)에서 X11 서버를 완전히 제거**하겠다고 선언했습니다. 이로써 레거시 X 윈도는 점차 역사의 뒤안길로 사라지고 있습니다.
3. **호환성 유지 (XWayland)**:
   - 아직 Wayland를 직접 지원하지 않는 수많은 구형 프로그램들을 위해, Wayland 내부에서 구형 프로그램을 가상으로 돌려주는 호환 레이어인 **`XWayland`** 가 내장되어 있어 기존 프로그램을 실행하는 데 아무런 지장이 없습니다.
4. **하드웨어 지원 (NVIDIA)**:
   - 오랫동안 독점 드라이버 문제로 Wayland 지원에 소극적이었던 NVIDIA마저 최근 최신 드라이버에서 Wayland를 완벽 지원하기 시작하면서 마지막 걸림돌이 해소되었습니다.
