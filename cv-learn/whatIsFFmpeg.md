
> FFmpeg은 비디오/오디오 분야에서 만능 맥가이버 칼이라고 할 수 있는 오픈소스 소프트웨어다. 

## 1. FFmpeg이란 무엇인가?
- 이름의 의미: **FF**(Fast Forward, 빨리감기) + **MPEG**(동영상 압축 표준 기구)의 합성어
- 정의: 비디오, 오디오 및 기타 멀티미디어 파일과 스트림을 인코딩(압축), 디코딩(압축 해제), 트랜스코딩(변환), 다중화(Muxing), 역다중화(Demuxing), 필터링, 재생할 수 있는 멀티미디어 프레임워크이자 명령줄 도구(CLI)

> 유튜브, 넷플릭스, 트위치, 카카오톡, 크롬 브라우저, VLC 플레이어, OBS 스튜디오 등 전 세계에서 동영상을 다루는 거의 모든 플랫폼과 프로그램의 내부 깊숙한 곳에는 FFmpeg 라이브러리가 탑재되어 있음

## 2. 왜 만들어졌는가?(탄생 배경)
FFmpeg은 2000년, 천재 프로그래머로 유명한 **파브리스 벨라(Fabrice Bellard)**가 시작한 프로젝트로, 2004년부터 2015년까지 미하엘 니더마이어(Michael Niedermayer)가 이끌었다.
- 시대적 배경(1990년대 말 ~ 2000년대 초):
당시 멀티미디어 환경은 극도로 파편화되어 있었음. 마이크로소프트의 WMV, 애플의 QuickTime(MOV), 리얼네트웍스의 RealMedia 등 저마다 독자적인 비디오 규격을 썼고, 비디오 하나를 보려면 온갖 전용 플레이어와 코덱팩을 따로 설치해야 했음.
- 만들어진 이유:
**"어떤 포맷의 동영상이나 오디오라도 제한 없이, 운영체제(Linux, Windows, Mac)를 가리지 않고, 가볍고 빠르게 재생, 변환할 수 있는 완벽한 오픈소스 프로그램을 만들자"**는 목표로 시작됨.

## 3. FFmpeg은 도대체 뭘 하는 도구인가?
동영상 파일은 단순히 하나의 파일이 아니라, 대개 **[비디오 트랙 + 오디오 트랙 + 자막]** 이 하나의 **껍데기(컨테이너: mp4, mkv 등)**에 담겨 있는 형태입니다. FFmpeg은 이 모든 요소를 분해해서 자유자재로 다룸.

### (1) 핵심 기능
1. 포맷 변환 (Transcoding): AVI를 MP4로 변환하거나, 무거운 4K 영상을 저용량 1080p 영상으로 줄임
2. 패킷 재포장 (Remuxing / Stream Copy):
- CCTV 녹화에서 중요한 기능으로, 영상을 다시 압축(인코딩)하지 않고, 네트워크로 들어오는 원본 비디오 데이터 그대로 MP4 파일 껍데기에 담기만 한다. CPU를 거의 쓰지 않아 컴퓨터에 부담이 없음
3. 네트워크 스트리밍 처리: RTSP, RTMP, HLS, HTTP 등 거의 모든 통신 프로토콜을 이해하므로, CCTV가 송신하는 RTSP 스트림을 직접 받아와 저장하거나 다른 곳으로 재송출할 수 있음
4. 영상 편집 및 필터: 자르기, 합치기, 화면 크기 조절, 자막 입히기, CCTV 화면 위에 타임스탬프 찍기, 회전 등 프로그램 창 없이 명령어 한 줄로 수행함

### (2) FFmpeg의 3가지 실행 파일
보통 FFmpeg을 다운로드하면 세 개의 실행 프로그램이 있음
- `ffmpeg`: 변환, 스트리밍, 녹화 등 실제 작업을 수행하는 메인 엔진
- `ffprobe`: 미디어 파일의 속성(해상도, 비트레이트, 코덱, 프레임 수 등)을 분석해 주는 도구
- `ffplay`: FFmpeg 기반의 초간단 미디어 재생기

## 4. 어떻게 쓰는가?

기본적으로 GUI가 없고 터미널(명령 프롬프트/CMD)에서 텍스트 명령어로 제어함.

### 기본 명령 구조
```bash
ffmpeg [입력 옵션] -i [입력 파일/주소] [출력 옵션] [출력 파일]
```

### 사용 예시
1. 미디어 파일 정보 확인(ffprobe)
어떤 코덱과 해상도로 되어 있는지 확인할 때:
```bash
ffprobe video.mp4
```

2. 단순 포맷 변환(재인코딩)
AVI 영상을 MP4(H.264 코덱 + AAC오디오)로 바꿀 때:
```bash
ffmpeg -i input.avi -c:v libx264 -c:a aac output.mp4
```

3. CCTV 녹화
보통 CCTV 카메라는 RTSP(Real-Time Streaming Protocol) 프로토콜을 사용해 영상을 보냄. FFmpeg을 이용해 녹화할 떄는 보통 아래와 같은 구조를 씀
```bash
ffmpeg -rtsp_transport tcp -i "rtsp://admin:비밀번호@192.168.1.100:554/stream" -c copy record.mp4
```
- `-rtsp_transport tcp`: UDP 대신 TCP를 사용해 네트워크 불안정으로 인한 화면 깨짐(패킷 손실)을 방지함
- `-i "rtsp://..."`: 카메라의 실시간 스트림 주소를 입력값으로 받음
- `c copy`:
    - "코덱을 변환하지 말고 그냥 원본 그대로 복사해라"
    - 만약 이 옵션이 없으면 FFmpeg이 영상을 실시간으로 다시 압축하느라 CPU 점유율이 90~100% 까지 높아질 수 있음.
    - `-c copy`를 주면 CPU 점유율이 낮은 수준으로 유지되면서 안전하게 녹화가 가능함.
