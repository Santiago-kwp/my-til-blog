# 네트워크 기초 내용 정리

### 학습 목표 : 네트워크 관련 용어의 개념적 이해 및 상세 내용 정리

### 학습 내용 요약 :

- 처리량(실제 데이터 처리량 bps), 대역폭(고속도로 n차선), 트래픽 개념의 이해
- 네트워크 성능 분석 명령어 : ping, netstat, nslookup, traceroute, tcpdump 등
- TCP/IP 4계층 : 링크 → 인터넷 → 전송 → 애플리케이션 계층 구분
  - TCP, UDP 패킷 교환 방식 비교 (가상회선 vs 데이터그램)
  - TCP 연결 시 3-way handshake, 연결 해제 시 4-way handshake 과정
  - 링크 계층의 전이중화 통신(유선), 반이중화 통신(무선)
    - 반이중화는 수신과 송신을 동시에 할 수 없으므로 충돌 탐지나 충돌 회피 로직이 필요함 → CSMA/CD(유선), CA(무선 - 충돌 회피)
  - 이더넷 프레임 구조 및 송수신을 위한 캡슐화와 비캡슐화
- 각 네트워크 계층별 하드웨어 기기 : L7(ALB), L4(NLB) 스위치, 라우터, 브리지, NIC, AP 등
- HTTP/1.0 → 1.1 → 2.0 → HTTPS → 3.0 의 개념 및 특징
  - HTTP/1.0 : RTT 증가로 인한 지연을 이미지 스플리팅, 코드 압축, 이미지 64진법 인코딩을 통해 해결
  - HTTP/1.1 : keep-alive 옵션 표준화, HOL Blocking, 무거운 헤더 문제 존재
  - HTTP/2.0 : 멀티 플렉싱을 통한 HOL Blocking 문제 해결, 허프만 코딩을 통한 헤더 비트수 감축, 서버 푸시를 통해 클라이언트에게 html 말고도 css, js 함께 전달
  - HTTPS : SSL/TLS 계층 위에서 암호화 통신 제공
  - HTTP/3.0 : QUIC 계층의 UDP 기반 통신으로 빠른 최초 연결 제공. FEC (순방향 오류 수정) 메커니즘을 통해서 패킷 손실에 대한 회복 시간 단축

### 네트워크의 기초

- 처리량 (throughoutput) : 링크를 통해 전달되는 단위 시간당 데이터양 (bps, bit per seconds)
  - 처리량은 사용자들이 많이 접속할 때마다 커지는 트래픽, 네트워크 장치 간의 대역폭, 네트워크 중간에 발생하는 에러, 장치의 하드웨어 스펙에 영향을 받음
  - 대역폭(bandwidth): 주어진 시간 동안 네트워크 연결을 통해 흐를 수 있는 최대 비트 수로 🛣️ 이는 마치 고속도로의 차선 수와 같습니다. 차선이 많을수록(대역폭이 클수록) 더 많은 차(데이터)가 동시에 지나갈 수 있습니다. 단위는 주로 Mbps(초당 메가비트)나 Gbps(초당 기가비트)를 사용합니다. 대역폭은 네트워크 자체의 물리적, 기술적 한계를 나타내는 **잠재적 능력임.**
  - 트래픽(traffic) : 트래픽은 **네트워크를 통해 실제로 흐르는 데이터의 총량**을 말합니다. 🚗 대역폭이라는 고속도로 위를 실제로 지나가는 차들의 흐름과 같습니다. 사용자가 많거나 데이터 사용량이 급증하면 트래픽이 많아집니다.
  - 처리량은 **대역폭을 통해 특정 시간에 실제로 성공적으로 전송된 데이터의 양**입니다. 🚚 이는 고속도로의 차선(대역폭)이 아무리 많아도, 실제 교통 상황(트래픽)으로 인해 정체가 발생하여 **실제로 목적지에 도착한 차의 수**와 같습니다.
- 지연 시간 (latency) : 요청이 처리되는 시간을 말하며 어떤 메시지가 두 장치 사이를 왕복하는 데 걸린 시간
- UTP(Unshield Twisted Pair) : 절연체로 감싸여지지 않은 두가닥씩 꼬여 있는 케이블

### 네트워크 토폴로지와 병목 현상

- 네트워크 토폴로지 : 노드와 링크가 어떻게 배치되어 있는지에 대한 방식이자 연결 형태
  - 트리, 버스, 스타, 링, 메시형태가 있음
- 스푸핑 : LAN 상에서 송신부의 패킷을 송신과 관련 없는 다른 호스트에 가지 않도록 하는 스위칭 기능을 마비시키거나 속여서 특정 노드에 해당 패킷이 오도록 처리하는 것
  - (스푸핑X) 송신부 → 수신부
  - (스푸핑O) 송신부 → 악의적인 노드 → 수신부
- 병목 현상 : 네트워크 토폴로지가 어떻게 되있는지를 확인하고, 어떤 경로로 이루어져 있는지를 파악한 뒤 회선을 추가하거나, 대역폭을 크게 설정하는 등의 방법으로 병목 현상을 줄여야 한다.
  - 병목 현상의 주요 원인은 네트워크 대역폭
  - 네트워크 토폴로지
  - 서버 CPU, 메모리 사용량
  - 비효율적인 네트워크 구성

### 네트워크 성능 분석 명령어

- `ping` : Packet INternet Groper의 약자로 물체의 위치를 찾는 음파탐지기로부터 유래되었으며 Mike Muuss에 의해 개발되었다 (Grope의 뜻은 (앞이 보이지 않아) 더듬으며 가다라는 뜻이라 여기서 유래되었다)
  - 네트워크 상태를 확인하려는 대상 노드를 향해 일정 크기의 패킷을 전송
  - 해당 노드의 패킷 수신 상태와 도달하기까지 시간 등을 알 수 있음 ⇒ 해당 노드까지 네트워크가 잘 연결되었는지 확인
  - ICMP 프로토콜을 통해 동작하므로 네트워크 정책 상 ICMP 나 traceroute를 차단하는 대상의 경우 ping 테스팅이 불가능함.
- `netstat` : network status의 약자라고 생각되며 접속되어 있는 서비스들의 네트워크 상태를 표시하는 데 사용됨. 네트워크 접속, 라우팅 테이블, 네트워크 프로토콜 등 리스트를 보여줌
  - 주로 서비스의 포트가 열려 있는지 확인할 때 사용됨.
- `nslookup` : DNS에 관련된 내용을 확인하기 위해 쓰는 명령어로 특정 도메인에 매핑된 IP를 확인하기 위해 사용됨

### TCP/IP 4계층 모델

> 링크 계층 → 인터넷 계층 → 전송 계층 → 애플리케이션 계층으로 구분되며 특정 계층이 변경되었을 때 다른 계층이 영향을 받지 않도록 설계됨. 예를 들어 전송 계층에서 TCP 를 UDP로 변경하였다고 해서 인터넷 웹 브라우저를 다시 설치해야 하는 것이 아니듯 유연하게 설계된 것

애플리케이션 계층

- FTP, HTTP, SSH, SMTP, DNS 등 응용 프로그램이 사용되는 프로토콜 계층이며 웹 서비스, 이메일, 파일 전송 등 서비스를 실질적으로 사람들에게 제공하는 계층

전송 계층

- 송신자와 수신자를 연결하는 통신 서비스를 제공하며, 연결 지향 데이터 스트림 지원(TCP), 신뢰성, 흐름 제어를 제공하며 애플리케이션과 인터넷 계층 사이의 데이터가 전달될 때의 중계 역할을 함.
- **TCP(Transmission Control Protocol)** 은 패킷 사이의 순서를 보장하고 연결지향 프로토콜을 사용해서 연결을 하여 신뢰성을 구축해서 수신 여부를 확인하며 ‘가상회선 패킷 교환 방식’을 사용함
  - 엄밀히 말하자면 TCP는 가상 회선 접근 방식을 사용하긴하지만 데이터그램 패킷 교환 방식에 의존한다.
  - **TCP uses a virtual circuit approach, but relies on datagram packet switching at a lower level**. This is because the internet's core network layer protocol, IP (Internet Protocol), is connectionless and uses datagrams. TCP adds a reliable, connection-oriented service on top of this unreliable foundation.
- UDP(User Datagram Protocol)은 순서를 보장하지 않고 수신 여부를 확인하지 않으며 단순히 데이터만 주는 ‘데이터그램 패킷 교환 방식’을 사용함
- 가상회선 패킷 교환 방식(Virtual Circuit Packet Switching)
  - 데이터를 전송하기 전에 논리적인 경로 (가상회선)을 설정한 후, 모든 패킷들이 설정한 경로를 따라서 이동
  - 패킷들은 전송 순서가 보장하지만, 네트워크 상황에 따라 패킷들이 도착하는 순서는 일정하지 않을 수 있다. 하지만 패킷이 도착한 후, 순서 번호를 기반으로 재조립하여 원래의 전송 순서대로 데이터를 다시 정렬하는 방식을 사용한다 (책에는 전송된 ‘순서대로’ 도착한다고 대강 작성해놨지만 정확한 내용은 이와 같다)
- 데이터 그램 패킷 교환 방식
  - 패킷이 독립적으로 이동하며 최적의 경로를 선택하여 가는데, 하나의 메시지에서 분할된 여러 패킷은 서로 다른 경로로 전송될 수 있으며 도착한 ‘순서가 다를 수’ 있는 방식을 뜻함.
- TCP 연결 성립 과정
  - 신뢰성을 확보할 때 3-way handshake라는 작업을 진행함
  - `SYN` 단계 : 클라이언트는 서버에 클라이언트의 `ISN(Initial Sequence Numbers`, 초기 네트워크 연결을 할 때 할당되 32비트 고유 시퀀스 번호)을 담아 `SYN`을 보냄. `ISN`은 새로운 TCP 연결의 첫 번째 패킷에 할당된 임의의 시퀀스 번호를 말하며 장치마다 다를 수 있음.
  - `SYN + ACK` 단계 : 서버는 클라이언트의 ISN을 수신하고 서버의 ISN을 보내며 승인번호로 클라이언트의 `ISN + 1` 을 보냄
  - `ACK` 단계 : 클라이언트는 서버의 `ISN + 1` 한 값인 승인번호를 담아 `ACK`를 서버에 보냄
- TCP 연결 해제 과정
  - 연결 해제 시 4 - 웨이 handshake 과정이 발생한다.
  1. 클라이언트가 연결을 닫으려고 할 때 `FIN` 으로 설정된 세그먼트를 보냄. 그리고 클라이언트는 `FIN_WAIT_1` 상태로 들어가고 서버의 응답을 기다림
  2. 서버는 클라이언트로 `ACK`라는 승인 세그먼트를 보냄. 그리고 서버는 `CLOSE_WAIT` 상태에 들어감. 클라이언트가 서버의 `ACK` 세그먼트를 받으면 클라이언트는 `FIN_WAIT_2` 상태에 들어감
  3. 서버는 `ACK`를 보내고 일정 시간 이후에 클라이언트에 `FIN` 이라는 세그먼트를 보냄
  4. 클라이언트는 `TIME_WAIT` 상태가 되고 나서 다시 서버로 `ACK`를 보내서 서버는 `CLOSED` 상태가 됨. 이후 클라이언트는 어느 정도의 시간을 대기한 후 연결이 닫히고 (`CLOSED)` 클라이언트와 서버의 모든 자원의 연결이 해제됨.
  5. `TIME_WAIT` : 소켓이 바로 소멸되지 않고 일정 시간 유지되는 상태를 말하며 지연 패킷 등의 문제점을 해결하는 데 쓰인다.

  TCP 상태 변화 다이어그램

  ```
  클라이언트                           서버
  ESTABLISHED ──┐                 ┌── ESTABLISHED
                │                 │
                │ ①FIN            │
                ├─────────────────→│
  FIN_WAIT_1 ───┤                 ├─── CLOSE_WAIT
                │                 │
                │ ②ACK            │
                │←─────────────────┤
  FIN_WAIT_2 ───┤                 │
                │                 │
                │ ③FIN            │
                │←─────────────────┤
  TIME_WAIT ────┤                 ├─── LAST_ACK
                │                 │
                │ ④ACK            │
                ├─────────────────→│
                │                 │
     CLOSED ────┘                 └─── CLOSED

  ```

  **왜 TIME_WAIT이 필요한가?**
  1. **지연된 패킷 처리**
  - 네트워크에서 지연되어 도착하는 패킷들을 기다림
  - 새로운 연결과 충돌하지 않도록 방지

  [TIME_WAIT 상태와 데이터 무결성](https://www.notion.so/TIME_WAIT-267a84820e1380739b26c3e65c1a1754?pvs=21) 2. **마지막 ACK 재전송**
  - 서버가 마지막 ACK를 받지 못한 경우를 대비
  - 서버가 FIN을 재전송하면 ACK로 응답할 수 있어야 함
  3. **포트 재사용 방지**
  - 같은 포트로 새로운 연결이 즉시 생성되는 것을 방지
  - 이전 연결의 잔여 패킷과 새 연결의 패킷이 섞이지 않도록 함

인터넷 계층

- 인터넷 계층은 장치로부터 받은 네트워크 패킷을 IP 주소로 지정된 목적지로 전송하기 위해 사용되는 계층
- IP, ARP, ICMP 등이 있으며 패킷을 수신해야 할 상대의 주소를 지정하여 데이터를 전달함.
- 상대방이 제대로 받았는지에 대해 보장하지 않는 비연결형적(connectless)인 특징을 가짐

링크 계층

- 전선, 광섬유, 무선 등으로 실질적으로 데이터를 전달하며 장치 간에 신호를 주고받는 ‘규칙’을 정하는 계층.
- 네트워크 접근 계층이라고도 함

유선 LAN(IEEE802.3) : 유선 LAN을 이루는 이더넷은 IEEE802.3 프로토콜을 따름

- 전 이중화 통신(full duplex)
  - 양쪽 장치가 동시에 송수신할 수 있는 방식을 말함
  - 송신로와 수신로로 나눠서 데이터를 주고 받음 ⇒ 고속 이더넷은 이 방식을 기반으로 통신함.
- CSMA/CD
  - 반이중화 통신 중 하나인 Carrier Sense Multiple Access with Collision Detection (CSMA/CD) 방식을 사용했었음.
  - 데이터를 보낸 이후 충돌이 발생한다면 일정 시간 이후 재전송하는 방식을 말함
  - 한 경로를 기반으로 데이터를 보내기 때문에 데이터를 보낼 때 충돌에 대비

무선 LAN(IEEE 802.11) : 무선 LAN 장치는 수신과 송신에 같은 채널을 사용하기 때문에 반이중화 통신을 사용함

- 반이중화 통신(half duplex) : 양쪽 장치는 서로 통신할 수 있지만, 동시에는 통신할 수 없으며 한 번에 한 방향만 통신할 수 있는 방식. 즉, 하나의 데이터를 받기까지 전송이 제한된다.
- CSMA/CA(Carrier Sense Multiple Access with Collision Avoidance)
  - 유선 LAN의 CSMA/CD(Collision Detection)와 달리 충돌이 발생한 후 감지하는 것이 아니라, **충돌이 일어나기 전에 미리 방지**하는 것이 특징. 📡
  - 반이중화 통신 중 하나로 장치에서 데이터를 보내기 전에 캐리어 감지 등으로 사전에 가능한 한 충돌을 방지하는 방식을 사용하며 과정은 다음과 같음
    - 데이터를 송신하기 전에 무선 매체를 살핌
    - 캐리어 감지 : 회선이 비어 있는지 판단
    - IFS(Inter FrameSpace) : 랜덤 값을 기반으로 정해진 시간만큼 기다리며, 만약 무선 매체가 사용중이면 점차 그 간격을 늘려가며 기다림
    - 이후에 데이터를 송신함.
  - CSMA/CA의 동작 과정
  1. **Carrier Sense (반송파 감지)**:
  - 데이터를 보내려는 장치는 먼저 채널이 사용 중인지 확인합니다. 👂
  - 채널이 비어 있으면 데이터를 보낼 준비를 합니다.
  2. **Collision Avoidance (충돌 회피)**:
  - 장치는 즉시 데이터를 보내지 않고, **임의의 시간(Random Backoff)** 동안 기다립니다.
  - 이 임의의 시간은 여러 장치가 동시에 채널이 비어 있다고 판단했을 때 바로 데이터를 전송하여 충돌이 발생하는 것을 막아줍니다.
  3. **RTS/CTS (Optional, Request to Send / Clear to Send)**:
  - 혼잡한 환경에서는 RTS/CTS라는 추가적인 과정을 통해 충돌을 더 효과적으로 막을 수 있습니다.
  - 데이터를 보내려는 장치(송신자)는 먼저 작은 **RTS** 프레임을 보냅니다.
  - 수신자는 이를 받고 채널이 사용 가능하다는 것을 알리는 **CTS** 프레임을 보냅니다.
  - 주변의 다른 장치들은 이 RTS/CTS 신호를 듣고 특정 시간 동안 전송을 중단하여 충돌을 피합니다. 이를 통해 **'숨겨진 노드(Hidden Node)' 문제**를 해결할 수 있습니다.
  4. **Data Transmission & ACK (데이터 전송 및 확인 응답)**:
  - 모든 준비가 끝나면 송신자는 데이터를 전송합니다.
  - 수신자는 데이터를 성공적으로 받으면 **ACK(Acknowledgement)** 신호를 보냅니다.
  - 송신자는 ACK를 받으면 전송이 성공했다고 판단하고 다음 데이터를 보냅니다. ACK를 받지 못하면 데이터가 유실되었다고 판단하고 재전송합니다.

**이더넷 프레임**

데이터 링크 계층은 이더넷 프레임을 통해 전달받은 데이터의 에러를 검출하고 캡슐화하며 다음과 같은 구조를 가짐

```java
|<-- 7바이트 -->|<-- 1바이트 -->|<-- 6바이트 -->|<-- 6바이트 -->|<-- 2바이트 -->|<-- 46-1500바이트 -->|<-- 4바이트 -->|
|   Preamble  |      SFD     | Destination |    Source   |  Type/Length |   Data            |    FCS      |
|   Physical Layer Header    | MAC Address | MAC Address | IpV4/IPv6    | (Payload)         |             |
```

[이더넷 프레임 구조 및 에러 검출 메커니즘 상세](https://www.notion.so/267a84820e1380559579f964eb52f91c?pvs=21)

- Preamble : 이더넷 프레임이 시작임을 알림 → 수신 장치의 클럭 동기화, 수신기가 들어오는 신호를 인식하고준비할 시간 제공
  - **패턴**: 7바이트의 교대로 나타나는 1과 0 (0x55)
- SFD(Start Frame Delimiter) : 다음 바이트부터 MAC 주소 필드가 시작됨을 알림
  - 패턴 : 마지막 두 비트가 "11"로 프리앰블과 구별
- DMAC, SMAC : 수신자의, 송신자의 MAC 주소
  - MAC 주소 : 컴퓨터나 노트북 등 각 장치에는 네트워크에 연결하기 위한 장치(LAN 카드)가 있는데, 이를 구별하기 위한 식별번호를 말한다. 6바이트(48비트)로 구성됨.
- EtherType : 데이터 계층 위의 계층인 IP 프로토콜을 정의. IPv4 or IPv6
- Payload : 전달 받은 데이터
- FCS(Frame Check Sequence) : 에러 검출 비트 - 알고리즘 CRC-32

계층 간 데이터 송수신 과정

- 캡슐화 과정 (Data Encapsulation)
  - 애플리케이션 계층의 데이터가 전송 계층으로 전달되면서 ‘세그먼트’ 또는 ‘데이터그램’화 되며 TCP(L4) 헤더가 붙여짐. 이후 인터넷 계층으로 가면서 IP(L3) 헤더가 붙여지게 되며 ‘패킷’화가 되고, 이후 링크 계층으로 전달되면서 프레임 헤더와 프레임 트레일러가 붙어 ‘프레임’화가 됨.
  - 송신 과정

```
애플리케이션 계층
    ↓ [HTTP 데이터]
전송 계층 (TCP)
    ↓ [TCP 헤더 + HTTP 데이터]
네트워크/인터넷 계층 (IP)
    ↓ [IP 헤더 + TCP 헤더 + HTTP 데이터]
데이터링크 계층 (이더넷)
    ↓ [이더넷 헤더 + IP 헤더 + TCP 헤더 + HTTP 데이터 + FCS]
물리 계층
    ↓ [Preamble + SFD + 이더넷 프레임]
```

- 실제 프레임 예시

```
원본 데이터: "Hello World" (11바이트)
IP 패킷 크기: 31바이트 (IP 헤더 20바이트 + TCP 헤더 20바이트 + 데이터 11바이트)

이더넷 프레임:
- Preamble: 55 55 55 55 55 55 55 (7바이트)
- SFD: AB (1바이트)
- Dest MAC: AA BB CC DD EE FF (6바이트)
- Src MAC: 11 22 33 44 55 66 (6바이트)
- Type: 08 00 (IPv4, 2바이트)
- Data: [IP 패킷 31바이트 + 패딩 15바이트] (46바이트)
- FCS: XX XX XX XX (CRC-32, 4바이트)

총 크기: 72바이트
```

- 비캡슐화 과정
  - 하위 계층에서 상위 계층으로 가며 각 계층의 헤더 부분을 제거하는 과정을 말함
  - 캡슐화된 데이터를 받게 되면 링크 계층에서부터 타고 올라오면서 프레임화된 데이터는 다시 패킷화를 거쳐 세그먼트, 데이터 그램화를 거쳐 메시지화가 되는 비캡슐화 과정이 일어남. 그 이후 최종적으로 사용자에게 애플리케이션의 PDU인 메시지로 전달됨.

### PDU (Protocol Data Unit)

네트워크의 어떠한 계층에서 계층으로 데이터가 전달될 때 한 덩어리의 단위를 PDU라고 함. PDU는 제어 관련 정보들이 포함된 ‘헤더’, 데이터를 의미하는 ‘페이로드’로 구성되며, 계층마다 부르는 명칭이 다름

- 애플리케이션 계층 : 메시지
- 전송 계층 : 세그먼트(TCP), 데이터그램(UDP)
- 인터넷 계층 : 패킷
- 링크 계층 : 프레임(데이터 링크 계층), 비트(물리 계층)

> 예를 들어 애플리케이션 계층은 ‘메시지’를 기반으로 데이터를 전달하는데, HTTP의 헤더가 문자열인 것을 예로 들 수 있음. 그 이유는 헤더에 authorization 값 등 다른 값들을 넣는 확장이 쉽기 때문에 문자열을 기반으로 송수신함. ⇒ JSON과 같은 문자열 방식으로 데이터 송수신!

### 네트워크 기기의 처리 범위

- 애플리케이션 계층 : L7 스위치
- 인터넷 계층 : 라우터, L3 스위치
- 데이터 링크 계층 : 브리지, L2 스위치
- 물리 계층 : NIC, 리피터, AP

L7 스위치

- 스위치는 여러 장비를 연결하고 데이터 통신을 중재하며 목적지가 연결된 포트로만 전기 신호를 보내 데이터를 전송하는 통신 네트워크 장비
- L7 스위치는 로드밸런서(부하중재자)라고도 하며, 서버의 부하를 분산하는 기기. 클라이언트로 오는 요청을 뒤쪽의 여러 서버로 나누는 역할. 시스템이 처리할 수 있는 트래픽 증가를 목표로 함
- URL, 서버, 캐시, 쿠키들을 기반으로 트래픽을 분산함. 또한 바이러스, 불필요한 외부 데이터들을 걸러내는 필터링 기능 및 응용 프로그램 수준의 트래픽 모니터링도 가능함.
- 만약 장애가 발생한 서버가 있다면 이를 트래픽 분산 대상에서 제외해야 하는데, 이는 정기적으로 헬스 체크(health check)를 이용하여 감시하면서 이뤄짐

L4 스위치와 L7 스위치의 차이

- L4 스위치는 인터넷 계층을 처리하는 기기로 스트리밍 관련 서비스에서는 사용할 수 없으며 메시지를 기반으로 인식하지 못하고 IP 와 포트를 기반으로 트래픽을 분산함(특히 포트를 기반으로).
- 반면 L7 로드밸런서는 IP, 포트 외에도 URL, HTTP 헤더, 쿠키 등을 기반으로 트래픽을 분산함
- L7 스위치를 이용한 로드밸런싱은 ALB(Application LB), L4 스위치를 이용한 로드밸런싱은 NLB(Network LB) 컴포넌트로 함.

인터넷 계층을 처리하는 기기로는 라우터와 L3 스위치가 있음

라우터

- 여러 개의 네트워크를 연결, 분할, 구분시켜주는 역할을 하며 “다른 네트워크에 존재하는 장치끼리 서로 데이터를 주고받을 때 패킷 소모를 최소화하고 경로를 최적화하여 최소 경로로 패킷을 포워딩”하는 장비

L3 스위치

- L2 스위치의 기능과 라우팅의 기능을 갖춘 장비로 라우터는 소프트웨어 기반의 라우팅과 하드웨어 기반의 라우팅을 하는 것으로 나눠지고 하드웨어 기반의 라우팅을 담당하는 장치를 L3 스위치라고 함.

| 구분        | L2 스위치       | L3 스위치     |
| ----------- | --------------- | ------------- |
| 참조 테이블 | MAC 주소 테이블 | 라우팅 테이블 |
| 참조 PDU    | 이더넷 프레임   | IP 패킷       |
| 참조 주소   | MAC 주소        | IP 주소       |

데이터 링크 계층을 담당하는 브리지와 L2 스위치

L2 스위치와 브리지는 둘 다 **데이터 링크 계층(OSI 2계층)** 에서 동작하며, 네트워크 세그먼트를 연결하는 장치입니다. 🌉 이 둘의 주요 역할은 프레임의 MAC 주소를 기반으로 데이터를 전달하는 것입니다.

**브리지 (Bridge)**

브리지는 두 개의 네트워크 세그먼트를 연결하고 데이터를 필터링하는 간단한 장치입니다. 브리지는 다음과 같이 동작합니다.

- **MAC 주소 테이블 학습**: 브리지는 자신이 연결된 각 포트로 들어오는 프레임의 **출발지 MAC 주소**를 학습하여 MAC 주소 테이블을 만듭니다.
- **프레임 전달**: 프레임이 도착하면, 브리지는 **목적지 MAC 주소**를 테이블에서 찾아 해당 포트로만 프레임을 보냅니다.
- **필터링**: 목적지 MAC 주소가 들어온 포트와 같은 네트워크 세그먼트에 있으면, 브리지는 프레임을 다른 세그먼트로 전달하지 않고 버립니다(필터링).
- **충돌 도메인 분할**: 브리지는 충돌 도메인(Collision Domain)을 나누어, 네트워크 성능을 향상시킵니다. 하지만 **단 두 개의 네트워크 세그먼트만 연결**할 수 있다는 한계가 있습니다.

**L2 스위치 (L2 Switch)**

L2 스위치는 여러 개의 포트를 가진 **고속의 브리지**라고 생각할 수 있습니다. 스위치 역시 MAC 주소 테이블을 사용해 동작하지만, 브리지보다 훨씬 많은 포트를 지원하고 더 높은 성능을 제공합니다.

- **포트별 충돌 도메인 분할**: 스위치는 각 포트를 독립적인 충돌 도메인으로 분리합니다. 따라서 여러 장치가 동시에 데이터를 보내도 충돌이 발생하지 않아 **병렬 통신**이 가능합니다.
- **전이중 통신(Full-Duplex)**: 스위치는 각 포트에서 동시에 송수신을 할 수 있는 전이중 통신을 지원하여, 처리량이 크게 향상됩니다.
- **VLAN 지원**: 대부분의 L2 스위치는 가상 LAN(VLAN) 기능을 지원하여, 물리적인 위치와 관계없이 논리적으로 네트워크를 분리할 수 있습니다.

브리지와 스위치의 비교

| 특징            | 브리지 (Bridge)               | L2 스위치 (L2 Switch)         |
| --------------- | ----------------------------- | ----------------------------- |
| **포트 수**     | 2개                           | 다수 (4, 8, 16, 24 등)        |
| **속도**        | 상대적으로 느림               | 고속                          |
| **동작 방식**   | 소프트웨어 기반               | ASIC 칩 기반 (하드웨어)       |
| **충돌 도메인** | 2개로 분할                    | **각 포트마다** 분할          |
| **기능**        | 단순 필터링, 포워딩           | VLAN, QoS 등 다양한 기능 지원 |
| **용도**        | 소규모 네트워크 세그먼트 연결 | 대규모 LAN 구성의 핵심 장치   |

**결론적으로**, 브리지는 단순한 2포트 장치로 충돌 도메인을 나누는 역할을 했지만, L2 스위치는 그 기능을 확장하여 **다수의 포트를 가진 고성능 장치**로 발전했습니다. 현재는 브리지 대신 L2 스위치가 대부분의 LAN 환경에서 사용되고 있습니다

물리 계층을 처리하는 기기는 NIC, 리피터, AP가 있다.

NIC (Network Interface Card)

- 2대 이상의 컴퓨터 네트워크를 구성하는 데 사용하며, 네트워크와 빠른 속도로 데이터를 송수신할 수 있도록 컴퓨터 내에 설치하는 확장 카드.
- 💻 이더넷 카드, 무선 랜 카드 등이 NIC에 속합니다. NIC는 컴퓨터 내부의 데이터를 물리 계층의 전기 신호로 변환하고, 반대로 외부의 전기 신호를 컴퓨터가 이해할 수 있는 데이터로 변환하는 역할
- 각 LAN카드에는 주민등록번호처럼 각각의 기기를 구분하기 위한 고유의 식별번호인 MAC (Media Access Control) 주소가 있다.

AP (Access Point)

- **AP**는 유선 네트워크와 무선 장치(Wi-Fi 기기 등)를 연결하는 기기입니다. 🌐 AP는 무선 신호를 유선 신호로, 또는 그 반대로 변환하는 역할
- AP는 리피터와 유사하게 무선 신호를 증폭하는 기능도 있지만, 유선 네트워크의 한 지점으로서 무선 장치들이 네트워크에 접속할 수 있도록 **접근 지점(access point)** 을 제공하는 것이 주 목적입니다.
- 대부분의 가정용 AP는 라우터, 스위치 기능까지 통합되어 있어 무선 라우터라고도 함.

### IP 주소

ARP (Address Resolution Protocol)

- IP 주소로부터 MAC 주소를 구하는 IP 와 MAC 주소의 다리 역할을 하는 프로토콜
- ARP를 통해 가상의 논리적 주소인 IP를 실제 물리적 주소인 MAC 주소로 변환함.
- 그 반대의 역할을 하는 것은 RARP
- 특정 장치가 ARP 브로드캐스트를 보내서 IP 주소에 해당하는 MAC 주소를 알려달라고 하면, 해당하는 IP 주소의 장치가 그 장치의 MAC주소를 ARP reply 유니캐스트를 통해 MAC 주소를 반환하는 과정을 거쳐 IP 주소에 맞는 MAC 주소를 찾게 된다.

### HTTP/1.0

- 한 연결당 하나의 요청을 처리하도록 설계됨. 이는 RTT (Round Trip Time : 왕복 시간) 증가를 불러옴
  - RTT : 패킷이 목적지에 도달하고 나서 다시 출발지로 돌아오기까지 걸리는 시간이며 패킷 왕복 시간
- 서버로부터 파일을 가져올 때마다 TCP의 3-way handshake를 계속해서 열어야 하기 때문임

RTT의 증가를 해결하기 위한 방법

- 이미지 스플리팅 : 많은 이미지를 다운로드 받을 때 많은 이미지가 합쳐 있는 하나의 이미지를 받고, 이를 기반으로 background-image의 position을 이용하여 이미지를 표기하는 방법
- 코드 압축 : 개행 문자, 빈칸을 없애는 등 코드 크기 최소화
- 이미지 Base64 인코딩 : 이미지 파일을 64진법으로 이뤄진 문자열로 인코딩 → 37% 정도 크기가 더 커지는 단점은 있음.

### HTTP/1.1

- 매번 TCP 연결을 하는 것이 아니라 한 번 TCP 초기화를 한 이후에 keep-alive 라는 옵션으로 여러 개의 파일을 송수신할 수 있게 바뀜 (1.1 부터 표준화가되어 기본 옵션으로 설정됨)
- HOL Blocking (Head Of Line Blocking)
  - 네트워크에서 같은 큐에 있는 패킷이 그 첫 번째 패킷에 의해 지연될 떄 발생하는 성능 저하 현상
  - 예를 들어 image.jpg의 다운로드 속도가 느려지면 다른 것들이 대기하며 다운로드 지연이 생김
- 무거운 헤더 구조
  - 1.1 헤더에는 쿠키 등 많은 메타데이터가 들어있고 압축이 되지 않아 무거웠음

### HTTP/2

- SPDY 프로토콜에서 파생된 HTTP/1.x 보다 지연 시간을 줄이고 응답 시간을 더 빠르게 할 수 있으며 멀티플렉싱, 헤더 압축, 서버 푸시, 요청의 우선순위 처리를 지원하는 프로토콜
- 멀티 플렉싱
  - 여러 개의 스트림을 사용하여 송수신
  - 병렬적인 스트림을 통해 데이터를 서빙하고, 스트림 내의 데이터들도 쪼개져 있으므로 1.x 에서 나타나던 HOL Blocking문제를 완화할 수 있음.
- 헤더 압축
  - 허프만 코딩 압축 알고리즘을 사용하여 HPACK 압축 형식을 가짐
  - 허프만 코딩은 문자열을 문자 단위로 쪼개 빈도수를 세어 빈도가 높은 정보는 적은 비트 수를 사용하여 표현하고, 빈도가 낮은 정보는 비트 수를 많이 사용하여 표현해서 전체 데이터의 표현에 필요한 비트양을 줄이는 알고리즘
- 서버 푸시
  - HTTP/2는 클라이언트의 요청 없이 서버가 바로 리소스를 푸시 : 클라이언트가 html을 달라고 했는데 서버가 그냥 그 안에 있는 css 파일과 js 파일을 서버에서 푸시하여 클라이언트에게 먼저 제공

### HTTPS

- HTTP/2는 HTTPS 위에서 동작한다. 즉, HTTPS는 애플리케이션 계층과 전송 계층 사이에 신뢰 계층인 SSL/TLS 계층을 넣은 신뢰할 수 있는 HTTP 요청을 말한다. 이를 통해서 통신을 암호화함.
- SSL/TLS (Secure Socket Layer / Transport Layer Security Protocol)
  - SSL은 1.0부터 시작해서 2.0, 3.0, TLS 1.0, TLS 1.3까지 버전이 올라가며 마지막으로 TLS로 명칭이 변경되었으나, 보통 이를 합쳐 SSL/TLS로 많이 부름.
  - SSL/TLS는 전송 계층에서 보안을 제공하는 프로토콜. 클라이언트와 서버가 통신할 때 SSL/TLS를 통해 제3자가 메시지를 도청하거나 변조하지 못하도록 함
  - SSL/TLS 는 보안 세션을 기반으로 데이터를 암호화하며 보안 세션이 만들어질 때 인증 메커니즘, 키 교환 암호화 알고리즘, 해싱 알고리즘이 사용됨
  - 클라이언트와 서버와 키를 공유하고 이를 기반으로 인증, 인증 확인 등의 작업이 일어나는 단 한번의 1-RTT가 생긴 후 데이터를 송수신하는 것을 볼 수 있음
  - 클라이언트에서 사이퍼 슈트(cypher suites)를 서버에 전달하면 서버는 받은 사이퍼 슈트의 암호화 알고리즘 리스트를 제공할 수 있는지 확인함. 제공할 수 있다면 서버에서 클라이언트로 인증서를 보내는 인증 메커니즘이 시작되고 이후 해싱 알고리즘 등으로 암호화된 데이터의 송수신이 시작됨
    - 사이퍼 슈트 : 프로토콜, AEAD 사이퍼 모드, 해싱 알고리즘이 나열된 규약을 말하며, 아래의 5개가 있음
      - TLS_AES_128_GCM_SHA256
      - TLS_AES_256_GCM_SHA384
      - TLS_CHACAH20_POLY1306\_\_SHA256
      - TLS_AES_128_CCM_SHA256
      - TLS_AES_128_CCM_8_SHA256
    - AEAD 사이퍼 모드 : Authenticated Encryption with Associated Data 는 데이터 암호화 알고리즘이며 AES_128_GCM 등이 있음. 128비트의 키를 사용하는 표준 블록 암호화 기술과 병렬 계산에 용이한 암호화 알고리즘 GCM이 결합된 알고리즘을 뜻함
  - 인증 메커니즘 : CA(Certificate Authorities)에서 발급한 인증서를 기반으로 이뤄짐
    - CA에서 발급한 인증서는 안전한 연결을 시작하는 데 있어 필요한 ‘공개키’를 클라이언트에 제공하고 사용자가 접속한 ‘서버가 신뢰’할 수 있는 서버임을 보장함.
  - 암호화 알고리즘 : 키 교환 암호화 알고리즘으로는 대수곡선 기반의 ECDHE(Elliptic Curce Diffie-Hellman Ephermeral) 또는 모듈식 기반의 DHE(Diffie-Hellman Ephemeral)를 사용함
  - 해싱 알고리즘 : 해시 함수의 결과값이 특정 비트수인 알고리즘
- SEO에도 도움이 되는 HTTPS
  - 서비스를 운영한다면 검색엔진 최적화는 필수임. 이를 위한 방법으로 캐노니컬 설정, 메타 설정, 페이지 속도 개선, 사이트맵 관리 등이 있음

  캐노니컬(Canonical) 설정

  캐노니컬 설정은 여러 개의 URL이 **동일한 내용의 페이지**를 가리킬 때, 검색엔진에게 **대표 URL이 무엇인지 알려주는** 역할을 합니다. 🔗
  - **문제**: `https://example.com/product`, `https://example.com/product?ref=123`, `https://example.com/product/`와 같이 URL은 다르지만 내용이 같은 페이지가 많을 때, 검색엔진은 어떤 URL을 색인해야 할지 혼란을 겪을 수 있습니다. 이는 페이지 랭킹 분산으로 이어져 SEO에 불리합니다.
  - **해결책**: 페이지의 `<head>` 태그에 `<link rel="canonical" href="https://example.com/product">`와 같은 코드를 추가하여, 검색엔진이 `https://example.com/product`를 대표 페이지로 인식하고 해당 페이지에 모든 가치를 집중하도록 만듭니다.

    ***

  메타 설정 (Meta Tags)

  메타 태그는 웹페이지의 **콘텐츠를 설명하는 정보**로, 검색엔진에게 페이지의 내용을 명확하게 전달합니다. 📝
  - **메타 타이틀 (`<title>`)**: 검색 결과 페이지에 가장 크게 표시되는 제목입니다. 핵심 키워드를 포함하고, 페이지 내용을 명확하게 요약하는 것이 중요합니다.
  - **메타 설명 (`<meta name="description">`)**: 검색 결과 제목 아래에 표시되는 짧은 설명입니다. 사용자가 클릭하고 싶게 만드는 매력적인 문구로 작성하면 클릭률(CTR)을 높이는 데 도움이 됩니다.
  - **메타 키워드 (`<meta name="keywords">`)**: 과거에는 중요했지만, 현재는 대부분의 검색엔진이 무시하는 경향이 있어 큰 의미가 없습니다.

    ***

  페이지 속도 개선

  페이지 로딩 속도는 사용자 경험뿐만 아니라 검색엔진 랭킹에도 중요한 요소입니다. 🚀 느린 페이지는 검색엔진이 선호하지 않습니다.
  - **방법**: 이미지 압축, CSS와 JavaScript 파일 최소화, 브라우저 캐싱 활용, 서버 응답 시간 단축 등을 통해 페이지 로딩 시간을 줄여야 합니다. 구글의 **PageSpeed Insights**와 같은 도구를 사용하면 개선점을 쉽게 파악할 수 있습니다.

    ***

  사이트맵 관리

  사이트맵은 웹사이트의 모든 페이지와 콘텐츠를 나열한 목록 파일입니다. 🗺️ `sitemap.xml` 형식으로 만들어 검색엔진에 제출합니다.
  - **역할**: 검색엔진 크롤러가 사이트의 모든 페이지를 빠짐없이, 그리고 효율적으로 탐색하도록 돕습니다. 특히 신규 웹사이트나 복잡한 구조를 가진 사이트의 경우, 사이트맵이 없으면 일부 페이지가 누락될 수 있습니다. 정기적으로 업데이트하여 변경사항을 검색엔진에 알리는 것이 중요합니다.

### HTTP/3

- TCP 위에서 돌아가는 HTTP/2와 다르게 구글이 개발한 QUIC(Quick UDP Internet Connections)이라는 계층 위에서, UDP 기반의 전송 계층 프로토콜 기반.
- 멀티 플렉싱을 가지고 있으며 초기 연결 설정 시 지연 시간 감소라는 장점이 있음
  - UDP 기반이므로 통신을 시작할 때 3-way handshake 과정을 거치지 않아도 됨.
- QUIC은 첫 연결 설정에 1-RTT만 소요됨. 클라이언트가 서버에 어떤 신호를 한 번 주고, 서버도 거기에 응답하기만 하면 바로 본 통신을 시작할 수 있음.
- QUIC의 순방향 오류 수정 (Forward Error Correction, FEC)
  - QUIC은 **순방향 오류 수정(FEC)** 메커니즘을 사용하여 패킷 손실에 대한 회복 시간을 단축합니다. FEC는 데이터 전송 시 **원본 데이터와 함께 추가적인 복구 정보(패리티 데이터)** 를 함께 전송하는 기술
  - 동작 방식
    1. **그룹화**: QUIC은 여러 개의 데이터 패킷을 하나의 그룹으로 묶습니다.
    2. **패리티 패킷 생성**: 이 데이터 패킷들을 기반으로 **패리티 패킷**을 생성합니다. 패리티 패킷은 그룹 내 다른 패킷들의 정보를 조합하여 만들어집니다.
    3. **동시 전송**: 원본 데이터 패킷들과 이 패리티 패킷을 함께 수신자에게 보냅니다.
    4. **오류 복구**: 수신자는 패킷을 받아서 확인하고, 만약 **하나의 패킷이 손실**되었더라도, 나머지 패킷과 패리티 패킷을 이용하여 **재전송 요청 없이 손실된 패킷을 즉시 복구**할 수 있습니다.
  - 장점

    FEC를 사용하면 패킷이 손실되었을 때 **재전송을 요청하고 기다리는 시간(왕복 지연 시간, RTT)이 사라지므로**, 네트워크 지연이 심한 환경에서도 통신 효율이 크게 높아집니다. 이는 특히 모바일 환경이나 불안정한 무선 네트워크에서 큰 장점으로 작용함.
